# ShellBeam v0.1.6

## 更新内容

- 主机编辑器明确提供监控方式选项，新主机默认使用原有 SSH 无探针扫描。接入 ShellBeam Server 需要用户主动选择并确认；保存主机、绑定监控节点和安装自有探针分别操作，不会因扫描或刷新自动安装探针。
- 区分“SSH 无探针扫描”和常驻监控探针，修正采集状态及监控来源文案，减少将正常 SSH 采集误认为已安装探针的情况。
- MCP 接入改为“选择服务器 → 设置权限 → 核对并接入”三步流程，简化说明并明确授权范围。
- 服务器选择支持搜索、分组、仅看已选及连接账号选择；三态“全选”复选框只作用于当前筛选结果，并显示已选数量，保留隐藏选择和已选账号。
- 改进 Linux 安装包验收中的键盘焦点、下拉选择与主机运维状态就绪处理，保留严格身份、审计、通知和异常恢复验证。

## 数据与升级

- 应用标识保持 `app.shellbeam`，沿用现有 Vault、主机、凭据、MCP 授权、监控记录和 OperationJob 审计。
- 已有监控绑定与部署记录保留。切回 SSH 扫描不会自动卸载服务器上的探针；远端安装、升级、回滚和卸载仍需明确操作。
- MCP 的服务器选择与权限调整先作为草稿，最终确认前不会创建授权，也不会自动扩大已有客户端权限。
- 桌面升级不升级或重新部署 ShellBeam Server、监控探针和服务端扩展。结果未知的远端操作仍先读取状态，再由用户决定恢复动作。

## Highlights

- Explicit per-host monitoring choice, with SSH agentless scanning as the default for new hosts. Connecting ShellBeam Server, mapping a node and installing an owned probe remain separate, explicit actions.
- Clearer collection status and source wording, distinguishing SSH scans from resident monitoring agents.
- A three-step MCP setup flow with searchable and grouped server selection, connection accounts, filtered Select all and a visible selected count.
- Existing data, credentials, grants and audit history are retained. Draft selections do not grant access or broaden existing permissions.
