# 主机监控方式

监控方式按主机保存。新主机默认选择 **SSH 无探针扫描**；仅打开主机、扫描或发现监控节点，不会安装探针。

## 保持原有 SSH 扫描

1. 新建连接，填写原有 SSH 信息；保留「监控方式 → SSH 无探针扫描」。
2. 保存主机后，使用「检查状态」「刷新运维状态」或 Workspace 查看资源。
3. 扫描依赖 App 运行、Vault 解锁和 SSH 可达；不安装常驻探针，不要求接入 ShellBeam Server。

## 主动接入 ShellBeam Server

1. 编辑主机，在「监控方式」选择 **ShellBeam Server + 自有探针**。
2. 阅读确认说明并确认，再点击主机表单的「保存」。取消选择或取消保存不会改变已保存的方式。
3. 在「设置 → 监控与通知 → ShellBeam 监控」连接自己的 ShellBeam Server、核验服务并关联此主机。SSH 模式的主机不能新增监控绑定。
4. 展开该主机「运维详情 → 监控探针」，检查目标服务、节点、SSH 账号与签名版本后，单独确认安装。
5. 安装、升级继续使用现有自有探针发布源和原生签名/来源校验；选择监控方式本身不会安装 Server 或探针，也不会改变发布信任配置。

监控服务中直接「添加仅监控主机」也需要确认；此操作明确采用 Server 模式，不创建 SSH 凭据或安装探针。需要安装探针时先添加可用 SSH 连接。

## 切回 SSH 与保留规则

- 编辑主机选择 SSH，确认并保存后，主机和 Workspace 采用 SSH 数据；该主机不再参与 Server 指标采集。全部已关联主机均切回 SSH 时，后台跳过该服务的常规同步；手工发现服务仍是明确的只读操作。
- **远端已安装的探针和服务端通知不会因切换而自动停止。** 需要停止时，在原探针管理入口单独确认卸载或管理服务端规则。
- 监控关联、旧快照、节点、Vault 凭据和历史审计保留；SSH 模式仍允许检查、回滚、卸载和既有异常恢复，但不能新装、升级、接管或迁入探针。
- 老版本未记录监控方式的主机，根据原有监控绑定或托管探针记录保留 Server 模式；没有这些记录时使用 SSH。不会批量重置已接入主机。
- 方式变更与目录审计在同一事务保存；切换使旧同步版本失效，迟到结果不能重新覆盖当前选择。旧客户端省略该字段时保留已有选择。

本次为源码实现与隔离测试；尚未替换用户当前运行的安装包，也未对真实主机执行部署。

## “采集正常”不代表“探针已安装”

主机页的 `ssh-agentless` 表示 SSH 无探针扫描：通过临时 SSH 命令读取系统指标，不下载或注册常驻监控探针。历史界面把采集健康度标为“探针状态”、把采集结果标为“ProbeProvider 采集”，容易与安装状态混淆；现改为“采集状态”“监控采集”，并在当前来源处明确显示“SSH 无探针扫描”。

这些标签只描述当前数据的来源与采集结果，不证明服务器完全没有通过其他途径安装的探针。真实部署状态仍以探针部署记录、检查结果及安装/卸载审计为准。此修正仅影响展示，原始 provider ID、任务、告警身份、通知去重和历史记录不改写。
