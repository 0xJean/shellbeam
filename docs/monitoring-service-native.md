# 原生监控服务管理契约

PRD 0.5 C，2026-10-21。ShellBeam 承接日常接入、主机和通知设置，Komari 作为可选后端。此文记录已实现的边界；兼容 Agent 生命周期不在本批完成范围内。

## 用户入口

设置 → 监控与通知包含监控服务、主机离线规则和本设备提醒。接入既有服务时默认使用管理员登录，也支持已有 API Key；初始化仅用于用户已经部署但尚未初始化的服务。登录/初始化之后在同一个保存动作内验证并保存 API 凭据，继续发现、关联或导入主机。已有 ID、凭据引用、映射、快照和审计保留。

服务配置显示实际作用域：修改影响该服务上的全部主机，客户端关闭后仍生效。本设备通知设置只控制本设备。监控页面标题与本机连接名称分别标注，避免将别名误认为远端站点名称。日常设置没有整站 WebView 入口；没有监控服务的用户继续使用原连接目录。

## 已验证的远端协议

管理读写限定 1.6.x；实际验收版本为官方 1.6.0，hash `1b76b7ad5bc3de6529bb7f0577069b4ac241fec3`。

| 能力 | 请求及结果核验 |
| --- | --- |
| 首次初始化 | 读 `/api/install/status`，仅 `required:true` 时发一次 `/api/install/complete`；随后有界轮询版本和登录。安装路由不能事前返回版本，因此按已验证的安装契约处理；不覆盖已初始化服务 |
| 管理员授权 | `/api/login`，支持 `2fa_code`；从管理员设置复用已有 Key，仅为空时生成；通过 `/api/admin/client/list` 认证后直接写入 Vault；结束时注销短时登录 |
| 服务配置 | GET/POST `/api/admin/settings/`，只允许标题、说明、访问认证及受支持通知字段；只 POST 本次改变的字段，读回验证 |
| Webhook | `/api/admin/notification/channel/configuration`；GET 的完整渠道数据作为基线；编辑白名单字段并保留未知字段，提交后读回 |
| 渠道选择 | `/api/admin/notification/channels`；可保留和选择已有渠道 ID，原生配置编辑仅支持 Webhook |
| 历史保留 | RPC `admin:listMetricDefinitions` 与 `admin:updateMetricDefinition`；绑定 metric 名称及创建时间，允许 1–3650 天，禁止零天清空 |
| 测试通知 | 检查已启用有效渠道后仅调用一次 `/api/admin/test/sendMessage`；UI 报告服务接受，收件方需另行核实 |

HTTP 在原生层执行，20 秒超时、2 MiB 响应上限，不跟随重定向。原始远端错误、管理员密码、Cookie、API Key 和 Webhook 凭据不进入审计/错误提示。管理员密码不持久化，API Key 不通过授权命令返回前端；现有监控读取仍使用原 Vault 凭据路径。

## 保存与恢复

`monitoring_service_intents` 与 OperationJob 共用 SQLite 事务。意图元数据记录 Vault/服务、完整配置指纹、配置修订、目标、状态、任务 ID 和修订号；基线、期望及最近读回值使用 Vault 密钥 AES-GCM 加密。已有任务表不重建。

1. 用户确认保存；原生命令检查显式确认，保存意图及确认审计。
2. 核对当前 Vault 解锁代次、配置全文指纹及上下文。上下文五分钟到期，离开表单时撤销；每个 Vault/服务串行操作。
3. 读远端当前值，按改动字段三方合并。不同字段的外部变化保留，相同字段不同值进入冲突。
4. 在事务中记录 `applying`，再发送唯一一次写入。任何恢复都不从 `applying` 自动再次发写请求。
5. 读回相同字段及指标身份，得到 `verified`、`conflict`、`retry` 或 `uncertain`。写入响应丢失也先读回。
6. 跨会话只读取记录；用户可查看保存值、读回核验、明确重试或放弃。重试重新读取并只重新应用原修改字段，建立新任务；已匹配期望值时不重发。旧终态审计不改写，后续核验使用独立任务。

每服务最多保留 2000 个意图，界面按待处理优先显示最近 100 个；达到上限拒绝新意图而非删除历史。同目标及配置身份有未解决意图时，拒绝覆盖式保存。服务配置变化后旧意图不能向新目标写入，但仍可查看和放弃。原生层核对绑定与配置不是服务器签名身份；上游无条件写入，不能消除检查与提交间第三方并发覆盖的可能。

高风险确认覆盖初始化、指标保留策略及公开监控页面；重试不降低原有风险。已发请求无法由本机撤销，离开/锁库后结果不确定时保留审计，后续读回。放弃待处理意图也不声称撤销已发生的服务端效果。

## 当前缺口

- 兼容 Komari Agent 的原生安装、升级、签名发布、失败回退和卸载；不能用 ShellBeam Agent 的已有验证替代。
- 1.6.x 没有已核验的定时静默/负载规则管理接口；不把本地确认/归档包装成关闭服务器通知。
- 脚本及插件专属通知渠道、账户全生命周期管理尚未原生覆盖；已有配置保持原样。
- 完整资产字段、跨设备端到端冲突、多绑定删除/迁移及桌面/移动端安装包新流程验收仍需继续。

本批真实通知证据使用独立回环官方服务、合成上报及独立 HTTP 接收端，实际收到 Test/Offline/Online；没有修改用户 Vault 或重启正在运行的验收 App。详见验收矩阵。
